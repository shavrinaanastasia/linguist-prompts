# Аудит меток «Written in» в каталоге многоязычного корпуса

Корпус для сравнения лемматизаторов по типологическим признакам (WALS / Grambank) собран из нескольких источников. Каждый документ классифицировала локальная LLM (`qwen3.8:27b-mtp-128k`): она определила жанр, описываемый язык и язык или языки, на которых документ написан (поле «Written in»). Прежде чем строить на этих метках выборки по языкам, мы проверили, насколько им можно доверять.

Проверка охватила все **1715 кодов** из списка «Written in»: это 819 720 пар «документ — язык» на 742 070 классифицированных документов. Обращение шло через внутренний API каталога. Адрес сервера и учётные данные в репозиторий не попадают.

## Главное

1. **Модель придумывает ISO-коды по названию языка.** Код берётся не из справочника, а «угадывается» по первым буквам названия. В итоге документ получает код совсем другого, часто вымершего или крошечного языка. Как минимум 148 кодов с достаточной выборкой (≥ 5 документов) почти целиком заняты чужим языком, у 239 кодов виден этот «префиксный» след. Примеры:

   | Код в корпусе | Официально это | На самом деле в документах |
   |---|---|---|
   | `chc` (479 док.) | катоба | **чикасо** (`cic`), 476 из 479 |
   | `bar` (460) | баварский | **Bartangi Corpus**, бартангский (памирский, `sgh`) |
   | `goh` (344) | древневерхненемецкий | немецкий XVI–XVII вв. |
   | `puy` | пурисименьо | **пуюма** (`pyu`) |
   | `kav` | катукина | **кавалан** (`ckv`) |
   | `kot` | лагван | **котава** (`avk`) |
   | `dho` | дходия | **луо (Dholuo)** (`luo`) |
   | `prk` | южный ва | **пракрит** |
   | `par` | панаминт | **парфянский** (`xpr`) |
   | `koo` | конзо | **кунзиме** (`ozm`) |
   | `mbu`, `mbk`, `mer` | мбула-бваза, малол, меру | **мбуко** (`mqb`) |
   | `atq`, `moq` | аралле-табулахан, мор | **атикамек** (`atj`), **монтанье** (`moe`) |
   | `laz`, `sen`, `ser`, `kos`, `ram`, `tar` | арибвача, сенуфо, серрано, косраэ, канела, тараумара | **лазский, сенека, сери, коасати, рама, тариана** |

   Полный список — в [`data/suspected_mislabels.csv`](data/suspected_mislabels.csv). Коды, проверенные вручную по названиям документов, — в [`data/manually_reviewed_codes.csv`](data/manually_reviewed_codes.csv).

2. **Крупные языки размечены в основном верно.** Это санскрит (62 тыс.), тамильский (51 тыс.), гуджарати (34 тыс.), украинский, идиш, эстонский, адыгейский, баскский, табасаранский, удмуртский. Навахо (20 тыс.) — тоже настоящий навахо, но это статьи для Википедии, сгенерированные ботом. По документам ошибки затрагивают меньше 1% пар «документ — язык». Зато для малых языков они составляют значительную часть выборки, а иногда и всю.

3. **Счётчики языков завышены второстепенными метками.** В «Written in» перечислены все языки документа. Примерно в 36% пар язык не основной: у английского он основной лишь в 38% документов, у хинди — в 58%. Для выборок по языку нужно фильтровать по основному языку (первому в `written_languages`) или по доле языка (`share` в карточке документа). Оценки «сколько документов, если считать только основной язык» по каждому коду — в [`data/inflated_counts.csv`](data/inflated_counts.csv): 1203 кода, у которых в выборке язык основной меньше чем в 90% документов, примерно 292 тыс. лишних пар.

4. **Коды не нормализованы.** Справочник смешивает несколько стандартов:
   - коды ISO 639-2/B: `ger` (2 056 док.), `dut`, `rum`, `chi`, `tib`, `bur`, `arm`, `alb`, `mac`, `geo`, `baq`;
   - коды семей и групп: `inc`, `sla`, `nah`, `ber`, `nub`, `myn`, `sai` и другие, всего 39;
   - частные коды: `qan`, `qeq`, `qpa`;
   - служебные `und` (33 тыс., в основном PDF, из которых не извлёкся текст), `mis`, `mul`, `zxx`;
   - макроязыки рядом с отдельными языками: `ara`/`arb`, `zho`/`cmn`, `fas`/`pes`, `nep`/`npi`, `aze`/`azj` и т. д.

5. **Качество текстов важнее для лемматизации, чем метки.** Это выборочная проверка TXT по 25 документов на язык:
   - удмуртский: 10 из 25 в битой кодировке (cp1251, прочитанная как latin-1);
   - адыгейский: списки слов с POS-тегами, а не связный текст;
   - тувинский и украинский: в основном нижний регистр без пунктуации;
   - `gwi` (гвичин): 749 из 820 документов — GIF-картинки.

## Как проверяли

Для каждого кода брались до 1000 документов: первая страница API и одна случайная, по 500 документов. В названии и аннотации каждого документа (их писала та же LLM) искались названия языков из справочника каталога: 3006 описываемых языков с glottocode и ISO плюс названия из списка «Written in». Дальше документ попадал в одну из групп:

- **match** — упомянут сам язык метки (или родственный код: макроязык, B-код, диалект);
- **other** — упомянут только другой язык, не считая языков-посредников: английского, французского, испанского, русского, немецкого и т. п. (на них пишут словари и описания);
- **meta_only / none** — упомянут только язык-посредник или никакой.

Вердикт по коду:

- `mislabel` — ≥ 50% документов в группе other и < 25% в match;
- `partial` — ≥ 20% документов в группе other;
- `unverifiable` — < 30% в match;
- иначе `ok`.

Для языков-посредников вердикт не ставится (`n/a-metalanguage`). Флаг `prefix_signature` означает, что название самого частого «другого» языка начинается с букв кода. Колонка `confidence` отражает размер выборки: `low` — меньше 5 документов.

## Ограничения

- Аннотации написала та же модель, что ставила метки, поэтому их согласие не доказывает правильность метки. Расхождение же — сильный сигнал ошибки.
- У кодов с 1–4 документами вердикт ненадёжен. Для коротких названий языков возможны ложные совпадения: подсказка `suggested` указывает направление, а не готовый ответ.
- Языки, у которых в основном PDF (санскрит, тамильский, гуджарати), проверены по аннотациям, а не по тексту.
- Выборка случайная, поэтому повторный запуск даст немного другие проценты.

## Что предлагается исправить в конвейере

1. Не просить модель выдавать ISO-код. Пусть она называет язык (и, если может, самоназвание и регион), а код подбирается по таблице ISO 639-3 / Glottolog. Пару «код — название» нужно проверять по справочнику. Промпт для такой схемы — в [`prompts.md`](prompts.md).
2. Свести коды к ISO 639-3: B-коды заменить, коды семей и частные коды отправить на ручную разметку.
3. Хранить основной язык и долю каждого языка, а в счётчиках по умолчанию учитывать только основной.
4. Перед лемматизацией отфильтровать картинки, списки слов и тексты с битой кодировкой.
